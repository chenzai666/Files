# 标签切换性能重构

## 目标与基线

以已验证的 273d4ef74 为基线，借鉴 Pulse 复用标签状态和调度后台任务的方式，减少切换时的重复通知。继续使用 Files 现有页面和服务架构。

## 本次实现

- BaseTabBar 统一处理标签激活，只交接旧页面与新页面；重复选择不重新激活。
- 集合变化和普通选择共用入口，保留原有事件接口。
- MultiPanesContext 直接交接目标页面，避免空窗格和新窗格的两轮更新。
- 预览使用单个非重复计时器合并请求，执行时读取当前上下文；窗口关闭和服务释放时停止计时器。
- 日期刷新放入低优先级队列，同一页面最多保留一个待处理任务。
- 窗格 Loaded 时避免重复订阅焦点和鼠标事件。
- 标题直接读取当前标签数据，减少绑定时序导致的重复 Shell 图标读取。

每个标签仍复用原有 ContentFrame；关闭标签仍按原流程释放。没有新增常驻的隐藏页面可视树缓存。

## 回归范围

1. 多标签反复切换，检查目录、选中项、滚动和历史。
2. 新建、关闭、撤销关闭、最后标签关窗及恢复会话。
3. 切换后标签互换、拖出成窗、放到加号合并、文件悬停切换。
4. 标签转分栏、分栏还原标签、窗格焦点和分隔条、列视图。
5. 详情面板开关、无选中项、单选和多选、快速切换，最终预览跟随当前上下文。
6. 文件操作、搜索、标签、归档、网络、快速预览、外观和设置的功能入口保留。
7. 关闭窗口后查询 Windows 应用错误事件。

构建和有限回归不代表所有文件格式、Shell 扩展和网络环境均已验证；未执行项必须明确记录。

## 性能验证原则

在同一目录、标签数、视图和预览设置下比较，区分首次加载和已加载标签。检查整个 Files 进程组的内存与 CPU。没有同条件基线采样时不报告提速百分比，不承诺达到 Pulse 的资源占用。

## 后续方向

依据采样再评估页面布局缓存、目录枚举、缩略图队列及跨窗口状态传递。每项都以完整构建包和功能回归为验证单位。

## 拖出独立窗口的后续修复

用户反馈第一阶段版本拖出标签创建独立窗口仍有卡顿。同一测试目录、同一标签协议启动方式下，两次到窗口标题出现的基线为 2854 毫秒和 2713 毫秒；这不是完整首帧或目录可交互时间。

针对路径调整：

- 拖出标签的协议启动跳过普通启动画面及其等待。
- 仅 folder 协议参数执行短路径转长路径查询，序列化标签不再进入 StorageFolder 路径查询。
- 启动失败保留源标签；系统接受启动请求后，排队移除和释放源标签，避免在拖动回调中直接重建源布局。
- 完整测试构建显式启用 C# 代码优化，保留原有运行时、资源和功能。

待完整构建后再次运行相同测量，并检查窗口关闭错误事件及用户拖动体验。代码优化的效果也须以实际测量为依据。

## 启动预编译验证

728892419 的同条件测量为 2811 毫秒和 2854 毫秒，未显示出新窗口启动时间改善；不能记为卡顿已解决。该包的 Files.dll 原生代码目录为空。

下一次完整构建在还原和编译中启用 ReadyToRun，保留未裁剪的原有功能和资源。构建步骤直接从最终 MSIX 读取 Files.dll 的 PE 原生头，检查 RTR 签名；未包含预编译代码时构建失败，防止仅设置参数但最终包没有生效。仍须在本机重复测量并验证功能。

## 预编译完整包实测与关闭问题

b59b1668d 的最终 MSIX 和本机主程序集均通过 RTR 原生头检查。同条件两次窗口标题出现耗时为 2014 毫秒、1984 毫秒，较 ecdeb550e 的 2854 毫秒、2713 毫秒约缩短 0.8 秒。每组仅两次观察，指标不代表完整首帧、目录可交互时间或内存下降。用户反馈：“新窗口更快，原功能正常”。

复测期间仍出现一条当前完整包的崩溃记录。转储显示 DispatcherQueueController.ShutdownQueue 期间 DispatcherQueueTimer.TimerCallback 触发 stowed exception，原始 HRESULT 为 0x8000FFFF。小型转储没有保存原始异常栈，不能据此确定具体计时器或认定预编译导致崩溃。

代码核对发现，跨窗口合并和分栏拆分完成仍在原生拖动回调内同步移除源标签，最后一个标签还会同步关闭窗口。后续修复将该清理排入低优先级 UI 队列，并记录待关闭标签，阻止另一个拖动收尾回调重复关闭或重新创建窗口。继续复用原有 CloseTab、会话保存和撤销关闭流程。

该关闭时序修复须使用同次完整构建安装，验证排序、拖出、分栏还原及放到加号合并，并查询安装后的崩溃或挂起事件。不能将构建通过记为关闭崩溃已解决。
